# Changelog

## 0.8.4

- Каталог моделей Codex (`codex debug models`) разбирался сплошным обходом
  дерева и по устаревшим именам полей: уровни усилий всегда читались как
  `null`, `service_tiers` внутри записи модели давал фантомную модель
  `priority`, а уровень `ultra` не доходил до вызывающего. Разбор переписан
  под реальную схему каталога, формат кэша версионирован.
- Каталог моделей больше не разрешающий список — он оказался eventually
  consistent (новая модель отвечала в `codex exec` раньше, чем появлялась в
  `codex debug models`). Незнакомая модель теперь проходит с пометкой,
  решение остаётся за API.

## 0.8.3

- Лента хода работы в ответе инструмента начинается с самого вопроса. Прежде
  строка `asks:` уходила только в `notifications/progress`, а в ответ шёл
  журнал событий Codex, где вопроса нет: читатель видел, что модель запускает
  команды и дёргает инструменты, но не видел, о чём её спросили, и угадывал
  задачу по действиям.

## 0.8.2

- Существенные шаги больше не теряются в ленте хода работы. Уведомления идут
  не чаще чем раз в 250 мс, и прежде в пачку помещался только последний шаг:
  если модель за четверть секунды успевала запустить команду, дёрнуть
  инструмент и прочитать файл, до клиента доходило одно из трёх. Теперь такие
  шаги ждут очереди и уходят по одному, а схлопываются только размышления и
  план — они приходят потоком и повторяются. Очередь ограничена 32 шагами:
  если клиент отстаёт сильнее, старые шаги уже неинтересны.

## 0.8.1

- Лента хода работы начинается с самого вопроса: `· asks: …` перед первым
  действием модели. Прежде в клиенте было видно, чем Codex занят, но не было
  видно, о чём его спросили — вопрос приходилось угадывать по действиям.
  Строка берётся из того поля, где вопрос лежит у конкретного инструмента
  (`question`, `message`, `task`, `focus`), схлопывается в одну строку и
  обрезается: лента не место для промпта целиком.
- README больше не обещает живую ленту. Плагин действительно шлёт
  `notifications/progress` по ходу вызова, но Claude Code собирает их в блок
  вывода вызова инструмента, а ответ модели приходит целиком в конце. Сказано
  прямо и то, чего нельзя: прочитать ответ по мере написания и перебить
  на полуслове.

## 0.8.0

Плагин переименован в **Tandem**. Изменение ломающее — команды и переменные
окружения называются иначе.

- Команды: `/codex-bridge:ask` → `/tandem:ask`, и так все четырнадцать.
  Агенты: `codex-bridge:gpt-chat` → `tandem:gpt-chat`.
- Переменные окружения: `CODEX_BRIDGE_MODEL` → `TANDEM_MODEL` и остальные
  двенадцать по тому же правилу. Старые имена не читаются.
- Установка: `/plugin marketplace add VlDubr/tandem`, затем
  `/plugin install tandem@tandem`. Репозиторий переименован, GitHub
  перенаправляет старые ссылки, но команду установки нужно обновить.

Почему: прежнее имя занимали двадцать с лишним репозиториев, а `codex-bridge` —
активный проект на 249 звёзд с близким позиционированием. Имя из двух чужих
торговых марок не отличало проект ни от них, ни от официального плагина OpenAI,
и не говорило, что он делает. Тандем — двое, работающие одну задачу вместе,
и это ровно то, чем плагин является.

Функциональность не менялась.

## 0.7.3

- Неудачная проба возможностей `codex exec` больше не выдаётся за достоверную.
  `capabilities()` считала help прочитанным по одному признаку — непустому
  выводу, — но сломанный, зависший или незнакомый бинарь пишет в stderr текст
  ошибки, и он так же непуст. Такая проба давала `probed: true` при всех флагах
  `false` и записывалась на диск с валидным ключом версии, то есть переживала
  перезапуск сервера. В основном пути это вырождало `buildArgs` в
  `["exec", "-"]`: терялся `--cd`, и Codex уходил работать в каталог процесса
  вместо каталога проекта, а вместе с ним пропадали `--sandbox`,
  `--skip-git-repo-check` и `--json`. Теперь пробой считается только штатно
  завершившийся help — без ошибки запуска и с нулевым кодом возврата, — а
  неудачная проба не кэшируется ни на диске, ни в памяти: следующий вызов
  пробует снова, до тех пор действует прежний запасной набор базовых флагов.
- Тест `1d` больше не зависит от порядка прогона. `image-core.mjs` берёт
  возможности из `codex-core.mjs`, а тот держит их в модульной переменной;
  query-параметр в динамическом импорте создаёт новый экземпляр только самого
  `image-core`, поэтому проба выполнялась один раз за прогон и тест читал чужой
  результат. На POSIX он падал с самого своего появления, на Windows
  пропускался и потому не был виден.
- Метаданные плагина и панель настроек переведены на английский: карточку из
  `marketplace.json` показывают каталоги плагинов, а заголовки параметров —
  сам Claude Code. Ключевые слова дополнены теми, по которым плагин ищут.
- README: первый экран переделан в витрину с демо-гифкой, таблицей направлений
  моста и командами установки; добавлен раздел со сценариями использования.
  Раздел про безопасность теперь отвечает и на главный вопрос — какой код
  уходит в OpenAI. Пример ленты хода работы в английской версии больше не
  выводит русские подписи.
- `docs/example-debate.md` — настоящий разбор, в котором GPT нашёл дефект кэша
  возможностей, с выводом проверки и ссылкой на коммит.

## 0.7.1

Исправления по итогам сплошного code-review. Три независимых прохода — два
Codex и один Claude — дали 48 находок; здесь закрыты все, кроме отложенных
явно.

Отказы и живучесть:

- Скалярное JSON-сообщение (`null`, строка, число) больше не роняет MCP-сервер.
  Прежде деструктуризация такого сообщения выбрасывала исключение в
  асинхронном обработчике readline, и вместе с сервером умирали все идущие
  вызовы. То же исправлено в JSON-RPC-клиенте app-server, где падение воркера
  оставляло задачу без кода возврата.
- У входящего сообщения появился предел размера: разбор строки произвольной
  длины удваивал расход памяти.
- Воркер завершает задачу по событию `close`, а не `exit`, и публикует код
  возврата только после того, как журнал дописан на диск. Прежний порядок
  позволял читателю увидеть завершение раньше последних строк ответа и принять
  обрезанный вывод за полный.
- Сбой чтения промпта больше не оставляет Codex ждать закрытия stdin до самого
  таймаута: промпт читается до запуска процесса.
- `killTree` на POSIX эскалирует до `SIGKILL`, если процесс пережил `SIGTERM`.
  Прежде функция сообщала об успехе, ничего не завершив.

Учёт задач и расход квоты:

- Воркер публикует метку жизни, и она заменила pid как признак работающей
  задачи. Переиспользованный номер процесса больше не выдаётся за живой воркер
  и не может быть убит страховочным таймаутом.
- Отменённая задача остаётся в учёте, пока жив её процесс: прежде `codex_cancel`
  сразу помечал её терминальной, и предел параллельных задач обходился одной
  отменой.
- Запись о задаче создаётся до запуска воркера, а не после. Сбой между
  запуском и записью оставлял процесс Codex, о котором никто не знал.
- Границей расхода квоты у нативного ревью стала отправка `review/start`, а не
  ответ на него. Явный JSON-RPC-отказ по-прежнему разрешает `codex exec`:
  он доказывает, что ревью не началось.
- Замки старта и чата снимаются переименованием, а не парой rmdir и mkdir:
  между ними замок успевал взять другой процесс, и следующий rmdir снимал уже
  чужой живой. Владелец замка чата обновляет метку времени, поэтому замок
  больше не протухает посреди хода.
- Хранилище задач убирается за собой: журналы и промпты старше недели, а также
  всё сверх двухсот завершённых задач, удаляются.

Контекст ревью:

- Файлы, похожие на хранилища учётных данных, вырезаются и из отслеживаемого
  дифа тоже. Прежде фильтр стоял только на новых файлах, и изменение уже
  добавленного в репозиторий `.env` уходило модели построчно.
- Отсутствие общего предка с базой — явный отказ вместо молчаливого сравнения
  с самой базой.
- Новый файл читается через дескриптор, открытый без разыменования ссылок:
  между проверкой и чтением по имени файл успевал стать симлинком наружу.
- Список имён и журнал коммитов в сводке ограничены сверху.
- Многобайтные символы переживают границу чтения журнала.

Обвязка:

- `claude_task` с правом записи требует непустой административный allowlist.
  Прежде отсутствующий или пустой `task_tools` открывал Claude все инструменты
  в режиме `acceptEdits`.
- Пути изображений проверяются по реальному пути: symlink или junction внутри
  проекта больше не уводит чтение и запись наружу.
- Генерация изображения в MCP-пути стала асинхронной и принимает отмену:
  прежде она блокировала сервер на все четыре-пятнадцать минут.
- Дочерние процессы Claude снимаются с учёта по факту смерти, а не по отправке
  сигнала; предел вывода стал общим для stdout и stderr. После закрытия stdin
  мост дожидается идущих вызовов, останавливает proxy и уходит.
- Вложенный MCP-сервер переживает EPIPE и останавливается вместе с потомками.
- `setup --link-back` сообщает о конфликте и завершается ненулевым кодом,
  режим `config.toml` сохраняется при перезаписи, распознаётся форма
  `[mcp_servers."claude-bridge"]`, а `prefs.json` пишется под замком.

Наблюдаемость и мелочи:

- Потоковые дельты ответа и обновления счётчиков не пишутся в журнал, а
  счётчики токенов app-server переносятся в `turn.completed`: лента нативного
  backend снова показывает расход.
- Диф для нативного ревью собирается только как материал запасного пути.
  Невозможность его собрать больше не отменяет ревью, которому он не нужен.
- Таймаут задачи из настройки проверяется: отрицательное значение отключало
  таймер воркера и одновременно срабатывало в реконсиляции.
- `codex --version` вызывается с таймаутом: зависший бинарь останавливал сервер.
- Строки старого Codex без `--json` сохраняются как есть — обрезка отступов
  ломала в ответе блоки кода и разметку.
- Тестов стало 119: 91 выполняется на Windows, 28 требуют POSIX.
- Документация приведена в соответствие с кодом: структура каталогов, два
  backend ревью и граница отката, признак жизни воркера, предел параллельных
  задач, сбор изменений и его лимиты, срок хранения задач, язык наружных
  текстов, матрица CI. Из описания менеджера задач убран запуск через
  `/bin/sh`, которого нет уже несколько версий.

## 0.7.0

Нативный reviewer Codex как второй backend ревью. Проверено на живом
CLI 0.146.0: `review/start` принимает `threadId`, `target` и `delivery`,
отвечает `turn.id` и `reviewThreadId`.


- У `codex_review` появился второй backend — встроенный reviewer Codex через
  `codex app-server` и JSON-RPC `review/start`. Прежний `codex exec` остаётся
  основным и используется по умолчанию; новый путь включается только настройкой
  `review_backend: app-server`.
- `uncommittedChanges`, `baseBranch` и `custom` ReviewTarget строятся без
  вложения git diff в запрос к нативному reviewer. `focus` сохраняется через
  custom-цель, а обычное ревью рабочего дерева и ветки использует структурные
  цели протокола.
- Fallback на `codex exec` разрешён лишь до успешного ответа на `review/start`.
  После принятия turn разрыв соединения считается отказом: второй reviewer не
  запускается и квота ChatGPT повторно не расходуется.
- App-server работает внутри прежнего detached worker и пишет нормализованный
  JSONL-журнал. Поэтому `codex_status`, `codex_progress` и `codex_result`
  одинаково видят оба backend, а задача продолжает жить после перезапуска
  MCP-сервера.
- `codex_cancel` передаёт app-server точные `threadId` и `turnId` методом
  `turn/interrupt`. На Windows worker больше не уничтожается через `taskkill /F`
  до того, как протокольная отмена успеет уйти.

## 0.6.0

Английский стал языком по умолчанию, русский включается настройкой.

Плагин писался на русском целиком, включая промпты. Промпт на русском
заставляет и Codex, и Claude отвечать по-русски, поэтому для
нерусскоязычного пользователя это был не «плагин с русской документацией»,
а плагин, меняющий язык вывода.

- Новая настройка `language`: `en` по умолчанию, `ru` возвращает прежние
  тексты. Она задаёт язык описаний инструментов, сообщений и промптов, а
  значит и язык ответов вызываемой модели.
- Тексты вынесены в модули сообщений: `scripts/i18n.mjs` (промпты, описания
  инструментов Codex, ответы, сбор контекста ревью, менеджер задач, лента хода
  работы), `scripts/i18n-runtime.mjs` (воркер, диагностика, каталог моделей,
  проброс инструментов, обратный мост в конфиге Codex),
  `scripts/i18n-image.mjs` и `bridge/i18n-claude.mjs`. Недостающий перевод
  подменяется английским: пустое описание инструмента хуже описания на чужом
  языке.
- Лента хода работы переключается вместе с языком: «размышляет», «запускает»,
  «правит файлы» и остальные подписи приходят на выбранном языке.
- Язык доходит и до обратного моста: `link-back` записывает `CODEX_BRIDGE_LANG`
  в управляемый блок `~/.codex/config.toml`, поэтому сервер `claude-bridge`,
  который запускает сам Codex, отвечает на том же языке.
- Команды и агенты переведены на английский окончательно. Claude Code не
  подставляет язык в статические markdown-файлы, поэтому второго набора у них
  нет; на язык ответов моделей это не влияет — он задаётся промптами.
- Комментарии в коде остались русскими: их видит автор, а не пользователь.

  внутренняя ошибка сервера. Так же теперь отвечает и занятый тред чата.

## 0.5.0

Сбор изменений для ревью переписан. Раньше две его ветки собирали
непересекающиеся множества, и ни одна не покрывала обе: с `base` ревьюились
только коммиты, без `base` — только рабочее дерево. На ветке с коммитами и
незакоммиченными правками любой из двух вызовов молча показывал половину
картины, а описание параметра обещало «ревью всей ветки».

- С `base` собираются обе части, разделённые явно: «Изменения в коммитах» —
  то, что уйдёт в PR, «Ещё не закоммичено» — то, что не уйдёт. Модель видит
  разницу в статусе, а не однородную кучу строк.
- Без `base` и при чистом дереве берётся ветка по умолчанию (`origin/HEAD`,
  затем main/master/trunk). Раньше в этом случае ревью получало пустоту.
- Патч сверх порога больше не обрезается посреди hunk. Вместо обрезанного
  куска, который выглядит целым, модель получает `--shortstat`, список файлов
  со статусами и указание дочитать нужное самой. Размер оценивается по
  `--numstat`, без загрузки полного патча в память.
- Диф читается с `--no-ext-diff` и `--submodule=short`: чужой `diff.external`
  в конфиге репозитория подменял формат вывода, а полный диф подмодулей
  втягивал чужой репозиторий целиком.
- Новые файлы показываются содержимым, а не одними именами. Раньше новый файл
  на 400 строк модель видела как одну строку с путём.
- Содержимое вкладывается не вслепую: `lstat` вместо `stat`, поэтому по
  символической ссылке не читается файл за пределами репозитория; каталоги,
  двоичные и великоватые файлы перечисляются, но не раскрываются; `.env`,
  ключи, сертификаты и учётные данные не раскрываются никогда. Действуют
  пределы на файл, на сумму и на число файлов.
- Списки путей читаются через `-z`: имя файла с переводом строки больше не
  ломает разбор.
- Ссылка из `base` проверяется через `rev-parse --verify --end-of-options`
  и обязана указывать на коммит. Несуществующая ветка даёт понятный отказ,
  а не пустой диф.
- Ошибки git перестали быть невидимыми: сбой команды или отсутствие
  репозитория дают явное сообщение вместо «изменений нет».
- У каждой команды объявлен свой минимальный `allowed-tools`. Раньше поле было
  только у `/codex-bridge:setup`.

## 0.4.3

Обратный мост GPT → Claude перестал блокироваться, а проверка готовности
Codex — выполняться там, где она не нужна.

- `claude_ask`, `claude_critique` и `claude_task` запускают Claude асинхронно.
  Прежний `spawnSync` держал event loop до десяти минут: мост не отвечал на
  `ping`, не принимал отмену и выполнял параллельные вызовы по очереди. Ровно

  направлении оставался.
- Отмена вызова доходит до Claude: `notifications/cancelled` останавливает
  процесс вместе с его потомками, соседние вызовы при этом продолжают идти.

- Предел на вывод считается в байтах, а не в символах строки, и при
  превышении процесс останавливается с явной ошибкой вместо тихого усечения.
- Уход моста снимает все запущенные им процессы Claude: раньше закрытие Codex
  оставляло их править файлы без надзора.
- Проверка готовности Codex стала асинхронной, с таймаутом 4 секунды на шаг,
  кэшем на минуту и защитой от параллельного запуска. Раньше два `spawnSync`
  без таймаута выполнялись перед каждым вызовом любого инструмента.
- Инструменты, которые Codex не запускают (`codex_status`, `codex_result`,
  `codex_progress`, `codex_cancel`, `codex_chats`, `codex_use`,
  `image_check_params`), проверку больше не проходят вовсе.
- Зависшая проверка возвращает отдельную причину `probe_timeout`. Раньше она
  выглядела как «Codex не установлен» — на исправном Codex это дезориентирует.
- SessionStart-хук чинит путь обратного моста до проверки готовности, а не
  после, и ограничен таймаутом 15 секунд.

## 0.4.0

Разговор с моделями Codex и живая трасса их работы. Заодно починен фоновый
путь на Windows, где он не работал вовсе.

Исправления:

- Фоновая задача больше не запускается через `/bin/sh`: на Windows такого

- Отказ запуска Codex теперь даёт `failed` с причиной, а не «процесс исчез».
- Убран `spawnSync`: он блокировал event loop MCP-сервера на всё время работы
  Codex, сервер не отвечал на `ping`, и клиент рвал соединение с
  `MCP error -32000: Connection closed`. Долгие вызовы стали асинхронными.
- Истечение `wait_seconds` больше не убивает первую попытку и не запускает
  работу заново: та же самая задача продолжает идти тем же процессом, а вызов
  возвращает её id.
- Сводка размышлений не обрезается до первых 100 символов.

Новое:

- `notifications/progress`: пока Codex работает, его шаги видны в Claude Code
  по мере появления — рассуждения, команды, правки файлов, поиск. Счётчик
  монотонный, без `progressToken` уведомления не шлются.
- Настройка `progress_notifications` выключает ленту, не трогая остального:
  часть сборок Claude Code закрывает соединение с MCP-сервером, получив
  `notifications/progress` (anthropics/claude-code#47378, #53617). Отрисовка
  ленты в свёрнутом виде инструмента появилась в Claude Code 2.1.153.
- `notifications/cancelled` доходит до задачи: отменённый в Claude вызов
  останавливает Codex, а не оставляет его работать в фоне.
- `codex_chat` — разговор с моделью Codex как с отдельным собеседником:
  тред продолжается через `codex exec resume`, модель, уровень reasoning и
  рабочий каталог повторяются на каждом ходе. Параллельные ходы по одному
  треду блокируются, пропавший тред даёт явную ошибку, а не молчаливое начало
  нового разговора.
- `codex_chats` — список разговоров и удаление треда.
- `codex_use` — модель и effort по умолчанию для репозитория.
- Агент `gpt-chat`, команды `/codex-bridge:chat` и `/codex-bridge:use`.
- Настройка `reasoning_summary`: при `detailed` Codex присылает сводки
  размышлений, которых при `auto` может не быть вовсе. Полные рассуждения
  модели недоступны ни при каком значении — наружу идёт только сводка.
- `scripts/statusline.mjs` — активность живых задач в строке состояния
  (подключается пользователем вручную, чужой `statusLine` не затирается).
- Аргументы и результаты чужих MCP-инструментов не пересылаются в ленту, вывод
  команд усекается: там бывают секреты и мегабайты текста.
- Тестов: 59 (17 из них требуют POSIX и на Windows помечаются пропущенными).

- MCP-сервер не заявляет неподдерживаемую версию протокола, отвечает parse error
